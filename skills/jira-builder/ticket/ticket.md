# Ticket body

Read `../_common.md` first. Ticket text is written in **English**.

## Guidelines

- **Subject** — first line, single `#`, format `[Scope/Domain] Action Verb + Object`, max 16 words.
- **Extreme brevity** — total description under 150 words. No background details, conversational fillers or boilerplate.
- **Sections** — use the sections and ordering required by the Sprint Health Guide policy. Include optional sections only when the input or the policy requires them.
- **Gaps** — name missing information briefly; never invent acceptance criteria, scope or dependencies to fill a section.

## Steps

1. Decide what is wanted: a new ticket, a rewrite, or a reformat of an existing description.
2. Read the policy when policy-specific output is needed.
3. Extract only facts present in the input and the policy.
4. Write the Subject, then the description in the policy's section order.
5. Add a short readiness note when the user asked for it, or when a required section has no facts to fill it.

Worked examples of finished tickets: `example.md`.

For a Story Point value, switch to **points** mode — do not estimate inside a ticket body.
