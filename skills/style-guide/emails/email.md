# Email Style — Friendly & Formal

## Tone
- Default: friendly and conversational, including technical peer-to-peer asks.
- Address the reader with "you". Multi-recipient: "Hi [Name], colleagues,".
- Use contractions in friendly emails (don't, you're, we're).
- Keep the email focused. Prefer plain text.

## Structure
- Subject line: 40-60 characters, front-load the main point.
- Greeting (friendly): "Hi [Name]," or "Hello [Name],".
- Greeting (formal): "Dear [Name]," or "Dear [Team Name],". One clear recipient line.
- Body order: context → action → outcome → call to action.
- Help request: context and refs → what you checked → synthesis → numbered questions → clear ask.
- Formal HR/ops: reason → ask with date window → alternative if needed → temporary/revert → offer docs.
- Formal FYI: what happened (amount, channel, from/to) → why → attachment → offer docs if compliance asks.
- Formal advisory ask: profile and goal → numbered practical questions → clear next-step ask.
- Closing (friendly): "Best," or "Thanks," + name. Formal: "Kind regards," or "Best regards," + full name.

## Tone Variations
- Transactional: neutral, factual, minimal warmth.
- Support: empathy first, then the fix.
- Help request: due diligence first, then specific written questions.
- Formal: polite full sentences, limited contractions; for HR, payroll, operations, bank, and advisors.

## Vocabulary
- Friendly: "Let me know if you have questions.", "Happy to help.", "What I checked", "Just a quick note."
- Formal: "I would like to request...", "temporary measure", "Could you please clarify...", "I am happy to provide any additional documentation."

## Formatting
- One blank line between paragraphs. Prefer plain paragraphs and simple lists.
- Prefer plain text without `**` markdown bold. Use paragraphs and lists for emphasis.
- Numbered lists for 3+ questions; label question topics when helpful.
- In evidence lines, include exact amounts, accounts, commands, hosts, and results.
- Always write in English.

## Edge Cases
- Prefer async-friendly asks when the reader can reply without a call.
- Lead with request context; skip empty openers.
